# CameraVFX 设计概要

实测数字见 [RESULTS.md](RESULTS.md)。

## 1. 管线

```
UVC 采集卡 ─USB─> Media Foundation SourceReader（异步、低延迟、只取原生无压缩格式）
                    │ 采集回调：memcpy 进 D3D11 动态纹理（唯一一次 CPU→GPU 拷贝），同时检测重复帧
                    ▼
        ┌──────────────── 渲染线程 ────────────────┐
        │ 颜色转换（像素着色器）→ RGBA，源分辨率     │
        │ Pacer：显示时刻 → (帧 nA, 帧 nB, t)        │
        │ Maxine VideoFrameGeneration（显式 t）      │  CUDA
        │ Maxine TrueHDR（默认在源分辨率，10-bit）   │  CUDA
        │ Maxine VideoSuperRes（1080p → 4K）         │  CUDA
        │ Blit：等比缩放、SDR↔PQ、时间码条           │
        │ Present：flip-discard，最大帧延迟 1，      │
        │          VRR 下 tearing + 按排程时刻提交    │
        └───────────────────────────────────────────┘
```

* D3D 与 CUDA 只在两处交接：每个内容帧进入时一次（源分辨率），每个输出帧出来时一次。三个特效在同一条 CUDA 流上串行，中间不回 D3D。
* 线程：
  * MF 回调：上传、重复帧检测、时间码解码。
  * 渲染线程（MMCSS "Games"）：节奏、推理、合成、呈现，处理按键和设置。
  * vblank 线程：阻塞在 `WaitForVBlank` 上，给固定刷新模式提供显示时钟。
  * 音频线程（MMCSS "Pro Audio"）：WASAPI 采集和播放。
  * 表盘线程和日志写线程，均为低优先级；渲染线程只向它们的无锁队列写入，从不等待。
* 切换模型档位或采集格式时，加载在工作线程上进行；渲染线程继续取采集帧喂给源时钟，并画暂停画面。

## 2. 出帧节奏

### 2.1 两个时钟

| 时钟 | 观测 | 模型 |
|---|---|---|
| 源（采集卡） | 帧 n 上传完成、GPU 可用的 QPC 时刻 | `S(n) = a + n·P` |
| 显示 | vblank 时刻 | `V(m) = b + m·T` |

两者都是滑动窗口（源 240 帧，显示 600 次 vblank）上的最小二乘直线，剔除残差超过约 4 倍中位残差的点后再拟合一次。这样去掉 USB 和驱动的抖动，同时跟踪 ppm 级漂移。帧序号由 MF 采样时间按实测周期算出，丢帧在序号上留下空洞，不会拉歪时间轴。

### 2.2 显示时刻 → (i, t)

每个输出帧有一个显示时刻 V：固定刷新下是预测的 vblank，VRR 下是自己排定的提交时刻。

```
x = S⁻¹(V − D)        i = ⌊x⌋,  t = x − i
```

* 插值对是 x 两侧相邻的两张**内容帧** (nA, nB)，t 按它们的实际间隔归一化。重复帧只喂时钟，不进插值对。
* t ≤ ε 显示 nA，t ≥ 1 − ε 显示 nB（`snap`，默认 0.06），省掉一次推理。
* x 只增不减，内容时间不会倒退。
* 两个时钟的漂移只表现为 t 的相位缓慢滑动，不需要丢帧或重复帧。

### 2.3 延迟 D 的伺服

每个输出帧测一次 slack = 渲染开始时刻 − 所需最新帧的就绪时刻。控制器让 2 s 窗口内的最小 slack 停在余量 `margin`（1 ms）附近。一条比例规律，两个方向各有时间常数和速度上限（e = min_slack − margin）：

```
e < 0（slack 不够）：dD/dt = −e / 0.03 s，最多 8 ms/s
e > 0（有多余）：    dD/dt = −e / 0.5 s，e ≤ 4 ms 时最多 2 ms/s，e > 4 ms 时最多 8 ms/s
```

* 增大立即执行，0.25 ms 的欠缺就用满 8 ms/s，slack 缓慢被侵蚀（相位漂移、到达延迟爬升）时不会先迟到。
* 减小要求窗口已满 3/4、最近 5 s 没有迟到；固定刷新下还要先用新的 D 把整个窗口重新评估一遍，确认 slack 仍不小于余量。平时的多余（迟到罚的余量、抖动尖峰离开窗口）不超过 4 ms，按 ≤ 2 ms/s 还回，即 ≤ 0.2% 的播放速度变化；只有确认过的大段多余（开机、切换之后）才用 8 ms/s（≤ 0.8%）。
* 固定刷新且 Pc > 1 时，评估窗口用 D − margin（稀疏相位上时钟拟合噪声的保护）；Pc = 1 不加，延迟不变。
* VRR 下 V 随 D 平移，slack 与 D 一比一变化，窗口里存的是"超出 D 的部分"。固定刷新下 V 由 vblank 决定，slack 随 D 分段变化，所以按候选 D 重新评估。
* 迟到（所需帧在渲染开始时还没到）：D 立即加上欠缺量（最多半个内容周期）和余量，每个所需帧只罚一次，然后 5 s 内不减小。
* 源停顿或画面静止（下一张内容帧过了预期还没来）不算迟到：保持最后一张内容帧，不动 D。
* 切换采集模式后重新配置时，若信号频率不变，已识别的 Pc 保留，检测器也从它开始，不会先按 Pc = 1 播一秒再跳。
* 模式、内容周期 Pc、倍数 k 或补帧开关改变时，D 直接平移两个稳态值之差，不靠伺服慢慢追：

```
稳态额外延迟 = (k − 1)/k · Pc·P   VRR
             = Pc·P               固定刷新（相位任意）
             = 0                  不补帧
D ≈ 稳态额外延迟 + 渲染提前量 + 就绪抖动 + 余量
```

### 2.4 出帧方式

| 模式 | 行为 |
|---|---|
| `vrr` | 输出落在步长 Pc/k 的网格上：`V = S(x) + D`，x ∈ {锚点 + j·Pc/k}，锚点是内容节奏开始的那张内容帧，所以 t 只取 0, 1/k, 2/k…。下一个格点按时间取：至少比上一帧的显示时刻晚半步。D 变大时位置先停在上一帧（画面保持），翻页间隔仍是半步到一步半，不会出现一个长间隔；赶不上就跳到下一个格点（计入 skip）。在 V − lead 开始渲染，提交 GPU 工作后睡到 V 前 0.3 ms 才调用 `Present(0, ALLOW_TEARING)`，翻页间隔因此很准。 |
| `fixed` | 每个 vblank 一帧。默认晚锁存：睡到 V − lead 才开始渲染，`Present(1)`。显示频率与内容不成整数比时各种相位都会出现，额外延迟接近一整个内容周期。 |
| `passthrough` | 不插帧，每个信号帧到达就转换并呈现；`passthrough-sync 0` 立即提交，是延迟基线。 |
| `auto` | 先以 passthrough、sync 1 探测 2.5 s。DXGI 帧统计里每次 present 刷新次数 < 1.2 判为 VRR（且支持 tearing）→ `vrr`，否则 `fixed`。 |

渲染提前量 lead：单帧开销取 CPU 提交时间与 VFX GPU 时间 + 0.3 ms 的较大者，下限是最近 300 帧开销的 p99 + 0.75 ms。VRR 下到提交时刻 GPU 还没完成就加 0.25 ms，固定刷新错过 vblank 就加 0.5 ms；3 s 没有调整就减 0.1 ms，直到下限。上限是输出周期 − 0.5 ms，和倍数的保持规则用同一个余量：倍数能保留的帧，lead 一定盖得住它的开销。

### 2.5 按内容帧率自适应

60 Hz 信号里的内容常常更慢：30 帧游戏每帧发两遍，24p 是 3:2。只按信号帧插值的话，一半插值发生在两张相同的图之间。

* **重复帧检测**（`detect-repeats`，采集线程，上传时顺带）：隔行比较当前帧与上一张内容帧，数出变化超过阈值（YUV 6 级，RGB 8 级，RGB 转换带抖动噪声）的样本。全局变化比例 ≤ 2e-5、且每个 32×16 小块变化 ≤ 16 个样本才算重复；小块判据让光标、HUD 这类小物体不会被全局比例淹没。参考是上一张内容帧，缓慢渐变会累积超过阈值。
* **内容周期 Pc**（以信号帧计，60 帧 = 1，30 帧 = 2，24p = 2.5）：40 帧窗口内相邻内容帧间隔的均值，在 10% 以内吸附到允许值（默认对应 60/48/45/40/30/24/20/15 帧；`content-rates` 可以限定）。估计值连续 30 帧停在同一个允许值上才切换，60↔30 过渡期扫过的中间值不会生效。
* **倍数 k**（只在 VRR 下）：内容帧率达到 `fg-threshold` 时 k = 1，否则 k = `fg-multiplier`；再受两个上限约束：k × 内容帧率不超过显示器刷新率；生成一帧的 GPU 开销要放得进一个输出周期（升档要求开销 + 1.5 ms、lead + 1 ms 都放得下，保持只要求较大者 + 0.5 ms，避免来回跳）。被压低时状态行、表盘和弹窗写明原因。
* 源时钟始终用每个信号帧拟合（含重复帧），内容帧率变化时不用重置。
* 长时间重复后画面再动起来，插值从 nB − Pc 开始，因为这段重复帧就是 nA 的画面。
* passthrough 和 auto 探测按信号帧呈现，保证呈现频率在 VRR 范围内，避免低帧率触发显示器倍帧（LFC）导致误判。

## 3. 延迟指标

全部是 QPC 时间。`--csv` 逐帧记录；每 `report` 秒输出状态，`warmup` 秒后统计清零一次。

| 指标 | 定义 |
|---|---|
| `cap.sample_to_arrival_ms` | 驱动打的采样时间 → 采集回调。主要是 USB 传输 |
| `cap.upload_ms` | 回调开始 → 拷进 GPU 纹理完成 |
| `cap.interval_ms` | 相邻帧到达间隔 |
| `vfx.fg / hdr / sr / out / gpu_total` | CUDA event 计时的各段 GPU 时间 |
| `gpu.*` | D3D11 timestamp query 计时的 D3D 段 |
| `lat.arrival_to_shown_ms` | 用到的最新源帧到达 → 上屏。VRR 与立即模式下上屏取翻页（present 调用）时刻，固定刷新取 `GetFrameStatistics` 按 PresentCount 匹配到的实际 vblank；状态行写作 `arrival->flip` 或 `arrival->scanout` |
| `lat.content_to_shown_ms` | 画面内容的采样时刻（生成帧按 t 在两帧采样时间间插值）→ 上屏，即运动延迟；单峰分布，表盘的大数字就是它 |
| `loop.scanout_to_arrival_ms` | HDMI 回环：时间码里的预定显示时刻 → 采集到达 |
| `pace.delay_ms` / `pace.t` | 伺服的 D 和实际使用的 t |

* VRR 下 `SyncQPCTime` 是被拉长的 vblank 的起点，不是该帧开始扫描的时刻，所以 VRR 下用翻页时刻。
* ×2 补帧时"到达 → 翻页"是双峰的（t = 0.5 与 t = 0 的帧离新帧到达的时间不同），比较不同设置用"内容 → 翻页"。
* 采集卡内部和显示器本身的延迟要靠外部回路：`--timecode` + `--decode-timecode` 的 HDMI 回环，或 `--marker` 方块加光电二极管 / 慢动作拍摄。

## 4. 声音

WASAPI 共享模式，事件驱动。采集端默认取与视频采集卡同一物理设备（`ContainerId`）的音频端点，输出为系统默认设备。两端时钟的漂移用 PI 伺服微调播放采样率（`IAudioClockAdjustment`），缓冲稳定在目标值。音频比视频早时，按视频的"内容 → 翻页" p50 渐进补延迟（≤ 4 ms/s）；本来就晚则不处理。每次欠载缓冲目标加 3 ms（上限 30 ms），30 s 无欠载还回 1 ms。
