| 项目 | 配置 |
|---|---|
| 显卡 | RTX 5090，驱动 621.14 |
| 采集卡 | UGREEN 25173（USB，原生 YUY2 1080p60） |
| 显示器 | Dell AW2725QF，3840×2160，桌面 165 Hz，全屏时 G-SYNC / VRR 生效 |
| Windows HDR | 关闭（HDR 输出以色调映射方式预览） |

§1 测量时 PS5 待机，采集卡输出自己的"无信号"画面：时序是真实的（USB、驱动、frame server 全链路），画面是静态的。§4 是真实游戏画面。画质用合成运动图测（`--selftest`）。

## 1. 延迟（`tools/bench.sh 30`）

每种配置 30 s，第 10 s 统计清零一次。p50 / p99，单位 ms。

| 配置 | 输出 | D | 最新源帧到达 → 翻页 | 采样时间 → 翻页 | GPU（CUDA） | 帧间隔 |
|---|---|---|---|---|---|---|
| 直通，立即呈现 `--mode passthrough --passthrough-sync 0` | 60 | — | **0.25 / 0.33** | 10.0 / 10.3 | — | 16.66 / 16.92 |
| 直通，等 vblank `--passthrough-sync 1` | 60 | — | 到扫描 4.8 / 6.5 | — | — | 16.67 / 16.89 |
| 补帧 low，`--mode vrr --fg-multiplier 2` | 120 | 13.1 | **12.3 / 13.9** | 22.8 / 23.7 | 0.66 / 1.14 | 8.336 / 8.600 |
| 补帧 medium，VRR ×2 | 120 | 14.4 | 13.7 / 15.0 | 24.2 / 24.8 | — | 8.335 / 8.678 |
| **补帧 + TrueHDR + 超分 → 4K HDR，VRR ×2** | 4K 120 | 14.0 | **13.5 / 14.3** | 23.7 / 24.0 | **2.14 / 2.51** | 8.334 / 8.608 |
| 同上，VRR ×3 | 4K 180 | 16.4 | 10.9 / 16.7 | 26.2 / 26.6 | 2.20 / 2.59 | 5.556 / 5.828 |
| 同上，`--mode fixed`（165 Hz，晚锁存） | 4K 165 | 20.5 | 到扫描 14.1 / 21.7 | 28.0 / 28.7 | 2.30 / 2.43 | — |

加入重复帧检测后复测（`--no-detect-repeats`，否则静态画面全是保持帧）：全链路 VRR ×2 到达 → 翻页 **12.8 / 13.8**，D 13.4，GPU 2.15 / 2.55；固定 165 Hz 到扫描 6.8 / 18.7，D 19.5。

* 采集卡交付（采样时间 → 回调）稳定在 9.7–9.9 ms，几乎全是 USB 传输；上传进 GPU 0.21 ms。
* VRR ×2 的 D = (k−1)/k·P（8.33）+ lead（约 4.5，覆盖推理 p99 和提交开销）+ 余量（1），相对直通多约 13 ms。
* 固定刷新下 165 Hz 与 60 Hz 不成整数比，D 接近一个完整源周期。
* 帧间隔 p99 在目标值 +0.3 ms 以内，因为 VRR 下 present 被拖到排程时刻才提交。

## 4. 按内容帧率自适应

**真实 PS5 30 帧游戏**（VRR，`fg-quality = high`，`fg-threshold = 60`，`sr-quality = hb-ultra`，60 s `--csv`）：

* 稳定后 1726 个相邻内容帧间隔全是 2 个信号帧，只有 2 次是 3。
* 输出 59.9 fps（×2），t 只有 0 和 0.5，0 迟到。
* D 28.8 ms = 16.7（等下一张内容帧）+ 10.7（lead）+ 1（余量）。
* 到达 → 翻页 28.2 / 29.1 ms。GPU：补帧 high 5.9 ms + 超分 hb-ultra 3.4 ms = 9.4 ms，60 fps 的预算是 16.7 ms。

**合成源**（`--synthetic --synthetic-content-rate 30 --fg`，真实显示器，auto 模式）：约 0.8 s 识别出 30 fps，探测选 VRR，输出 60.0 fps；D 21.5 ms，到达 → 翻页 21.1 / 23.7 ms，0 迟到（理论 20.7 ms）。

**离线仿真**（`pacing_test`，60 Hz 信号、1.5 ms 抖动、20 ppm 漂移）：

| 场景 | 输出 | 迟到 | D p50（理论） |
|---|---|---|---|
| 30 帧内容，VRR ×2 | 60 fps，t ∈ {0, 0.5} | 0 | 21.42（20.67） |
| 30 帧内容，VRR ×4 | 120 fps | 0 | 29.74（29.00） |
| 30 帧内容，固定 120 / 165 Hz | 120 / 165 fps | 0 | 31.20 / 34.56 |
| 24p 3:2，VRR ×2 | 48 fps | 0 | 33.88 |
| 60→30→60 切换，VRR ×2 | | 0 | 13.08 → 21.47 → 13.11 |
| 60 帧内容中静止 1 s | 保持 | 0 | 13.09 → 最大 13.12 |

`pacing_test` 还覆盖固定 120/144/164 Hz（含 59.94 Hz 源和 ppm 漂移）、带尖峰的源、250 ms 源停顿：干净的源 0 迟到，内容时间不倒退，播放速度变化 < 1.2%，VRR 的 t 落在网格上（误差 ≤ 0.0012），源停顿只让 D 上升约 1 ms。节奏检测在 60↔30 切换时约 0.9 s 跟上，静止画面不触发切换。

## 5. 采集格式

驱动采样时间 → 回调 p50（1080p60）：NV12 7.5 ms，YUY2 9.9 ms，RGB24 15.1 ms，P010 15.1 ms。差别几乎全是 USB 传输量（约 424 MB/s）；YUY2 720p 是 4.5 ms。

RGB24 下采集卡的颜色转换带两帧周期的抖动：重复帧最多相差 7–8 级，新帧在几乎静止的画面里也有 ≥ 7.6e-5 的样本超过 8 级。所以 RGB 的重复帧阈值是 8（YUV 是 6），改后 30 帧游戏的内容帧率测得 30.1，间隔全为 2。

## 6. 声音

采集端 "HDMI (UGREEN 25173)" 按 ContainerId 自动匹配，输出 USB 声卡，48 kHz / 2 ch，两端设备周期 10 ms。

* 采集 → 播放 45 ms，速率微调稳定在 ±20 ppm 以内。
* 视频同时运行 40 s 内 0 欠载。
* 自动同步：视频延迟设为 100 ms 时音频跟到 100.0 ms；改到 150 ms 约 14 s 平滑过渡。
* 线程挂起 150 ms / 400 ms / 2.5 s 后都能自动恢复。

编解码在软件里验证：1080p 输出 64/64 解对，4K 输出经 2× 缩小后由 1080p 采集也是 64/64。没有接线实测。
