# 本机实测结果

**测试环境**

| 项目 | 配置 |
|---|---|
| 显卡 | RTX 5090，驱动 621.14 |
| 采集卡 | UGREEN 25173（USB，原生 YUY2 1080p60） |
| 显示器 | Dell AW2725QF，3840×2160，桌面 165 Hz，全屏时 G-SYNC/VRR 生效（auto 探测结果：每次 present 1.00 次刷新） |
| Windows HDR | 关闭（HDR 输出以色调映射方式预览） |
| 软件 | VFX SDK 运行时 1.3.0.0 |

> 测试期间 PS5 处于待机，采集卡输出的是它自己的"无信号"画面。所以**时序是真实的**（USB、驱动、frame server 全链路），**画面是静态的**。插帧质量用合成的运动测试图测（`--selftest`）。采集卡自带的信号发生器会在 59.94 Hz 和 60.00 Hz 之间切换，正好顺带检验了时钟漂移处理。

数据来源：`tools/bench.sh 30`。每种配置跑 30 s，前 10 s 为伺服收敛期，统计在第 10 s 清零一次。下表给出 p50 / p99，单位 ms。原始逐帧 CSV 和日志在 `out/bench/`。

## 1. 延迟

| 配置 | 输出 | D（伺服延迟） | 最新源帧到达 → 翻页 | 采样时间戳 → 翻页 | GPU 推理（CUDA） | 帧间隔 p50 / p99 |
|---|---|---|---|---|---|---|
| 直通，VRR 立即呈现 `--mode passthrough --sync 0` | 1080p→4K 60 | — | **0.25 / 0.33** | 10.0 / 10.3 | — | 16.66 / 16.92 |
| 直通，等 vblank `--sync 1` | 60 | — | 到达→扫描 4.8 / 6.5 | — | — | 16.67 / 16.89 |
| 插帧 low，VRR k=2 | 120 fps | 13.1 | **12.3 / 13.9** | 22.8 / 23.7 | 0.66 / 1.14 | 8.336 / 8.600 |
| 插帧 medium，VRR k=2 | 120 fps | 14.4 | 13.7 / 15.0 | 24.2 / 24.8 | — | 8.335 / 8.678 |
| **插帧 + TrueHDR + 超分 → 4K120 HDR**，VRR k=2 | 4K 120 fps | 14.0 | **13.5 / 14.3** | 23.7 / 24.0 | **2.14 / 2.51** | 8.334 / 8.608 |
| 同上，VRR k=3 | 4K 180 fps | 16.4 | 10.9 / 16.7 | 26.2 / 26.6 | 2.20 / 2.59 | 5.556 / 5.828 |
| 同上，固定刷新（逐 vblank、晚锁存） | 4K @165 Hz | 20.5 | 到达→扫描 14.1 / 21.7 | 28.0 / 28.7 | 2.30 / 2.43 | — |
| 插帧(VFX) + 驱动 RTX VSR + RTX HDR，VRR k=2 | 4K 120 fps | 15.2 | 8.2 / 16.2 | 25.0 / 26.0 | 3.05 / 4.27 | 8.334 / 8.605 |

**怎么读这张表**

* **采集卡交付本身约 10 ms。**MF 采样时间戳到我们回调被调用之间稳定在 9.7–9.9 ms（p99 ≈ 10.0），这一段是 USB 传输加 Windows Camera Frame Server。上传进 GPU 纹理只要 0.21 ms（p99 0.25–0.30）。源帧到达间隔的抖动很小，p99 偏离周期约 0.2 ms。
* **直通基线**：从帧到达到翻页只要 0.25 ms，所以管线本身几乎不增加延迟。
* **插帧 + 超分 + HDR，VRR 2×**：伺服延迟 D 稳定在 14.0 ms。这和设计公式吻合：(k−1)/k·P（8.33）+ lead（4.45，覆盖推理 p99 加提交开销）+ 余量（1 ms）。相对直通，**额外延迟约 13.3 ms**，其中 8.3 ms 是 2× 插帧在原理上必须付出的，其余约 5 ms 来自推理和安全余量。
* **固定刷新**：显示器频率（165 Hz）和源（60 Hz）不成整数比，各种相位都会出现，所以 D 接近一个完整源周期（20.5 ms）。有 VRR 就用 VRR，auto 模式会自动这样选。
* **k=3（180 fps）**：已经到这台显示器的刷新上限，D 增加到 (2/3)·P + lead。
* 帧间隔 p99 都在目标值 +0.3 ms 以内，因为 VRR 下 present 被拖到排程时刻才提交。

## 2. 推理耗时（`--selftest`，1080p 输入，CUDA event 计时）

| 阶段 | GPU p50 | p99 |
|---|---|---|
| Video Frame Generation low / medium / high（含一次输出拷贝，墙钟时间） | 1.08 / 2.48 / 6.85 ms | — |
| VideoSuperRes 1080p→4K：q1 low / q21 streaming-medium / q4 ultra / q23 streaming-ultra | 0.77 / 1.07 / 2.14 / 3.13 ms | 1.9 / 1.5 / 2.6 / 3.7 |
| TrueHDR 1080p | 0.34 ms | — |
| TrueHDR@1080p + VSR q21（10-bit） | 1.70 ms 合计 | 1.98 |
| VSR q21 + TrueHDR@4K | 1.96 ms 合计 | 3.40 |
| **FG low + TrueHDR + VSR q21（整条链）** | **2.09 ms 合计** | **2.35** |

原先估计 1080p60 → 4K120 HDR 的推理总量在 10 ms 量级，实测约 **2.1–2.5 ms**。TrueHDR 放在超分之前（源分辨率、10-bit 进超分）比放在之后（4K）更省。

## 3. 插帧质量（合成测试图，对比解析的地面真值，PSNR dB）

| 方法 | t=0.25 | t=0.5 | t=0.75 | 平均 |
|---|---|---|---|---|
| 重复上一帧（参考） | — | 21.89 | — | — |
| 线性混合 blend | 25.96 | 24.82 | 26.18 | 25.65 |
| Maxine VFG low | 29.44 | 28.26 | 29.22 | 28.97 |
| Maxine VFG medium | 31.29 | 29.91 | 30.53 | 30.58 |
| Maxine VFG high | 34.55 | 34.50 | 33.10 | 34.05 |
| 自研 NVOF 光流插帧 q0 | 27.11 | 29.29 | 27.23 | 27.88 |
| 自研 NVOF 光流插帧 q1 | 26.13 | 29.12 | 26.49 | 27.25 |
| 自研 NVOF 光流插帧 q2 | 27.12 | 25.37 | 27.08 | 26.52 |

自研 NVOF 插帧的 GPU 开销：每对帧第一次插值 0.30 ms，之后每次 0.12 ms（q0/q1）；光流本身在独立的光流引擎上异步执行。在它自己的测试集上（`build/nvof_test`），平移、物体运动、缩放都比 blend 高 12–30 dB（44–52 dB）。

这张合成图里有 64 px 周期的棋盘格，硬件光流会给出差整数个周期的"假匹配"向量，例如 (54,−64) 而不是真实的 (−10,0)。修复办法是每对帧额外跑一遍提案重选：用 16×16 块匹配打分，再对短运动给一点微弱偏好。修复后 PSNR 从 22–24 dB 提高到 26.5–27.9 dB。右侧条纹区是同一像素上叠加了两种运动，单个运动矢量表达不了，仍略低于 blend。

实时默认用 Maxine VFG：同等耗时下质量更高。真实采集下实测，NVOF q1 在 VRR 2× 时到达 → 翻页为 14.8 / 15.6 ms，插值 0.30 ms GPU。

## 4. 节奏仿真（`build/pacing_test`）

覆盖以下场景：固定 120/144/164 Hz（±ppm 漂移、59.94 Hz 源）、VRR k=2/k=3、带抖动和尖峰的源、250 ms 源停顿。全部通过。

* 稳态 D 等于理论值：VRR k=2 无尖峰时 13.1 ms；164 Hz 固定刷新时 20.1 ms。
* 干净的源下，固定刷新和 VRR 都是 0 迟到帧。
* 内容时间从不倒退；播放速度变化 < 1.2%；VRR 时间步落在网格上，误差 ≤ 0.0012。
* 250 ms 源停顿只让 D 上升约 1 ms（修复前 D 会冲到 80 ms 上限）。

## 5. 回环时间码

编码和解码在软件里验证过：1080p 输出解对 64/64；4K 输出经 2× 缩放后由 1080p 采集，也是 64/64。实际 HDMI 回环需要把显卡输出接回采集卡，没有在本机接线测试。

## 6. 新增功能的测量（配置文件 / 自适应补帧 / 声音 / 日志）

### 6.1 回归：加入重复帧检测和新节奏器后的全链路

`--no-fg-adaptive`（输入是静止的"无信号"画面，打开自适应时每帧都是保持帧，测不到管线延迟），其余同 §1：

| 配置 | 到达 → 翻页 / 扫描 p50 / p99 | D | GPU（CUDA）p50 / p99 | 帧间隔 p50 / p99 |
|---|---|---|---|---|
| 补帧 + TrueHDR + 超分 → 4K120，VRR k=2 | 12.8 / 13.8 ms（之前 13.5 / 14.3） | 13.4 ms | 2.15 / 2.55 ms | 8.334 / 8.601 ms |
| 同上，固定 165 Hz | 到扫描 6.8 / 18.7 ms | 19.5 ms | 2.22 / 2.46 ms | 6.05 / 6.87 ms |
| 直通 VRR | 0.26 / 0.32 ms | — | — | 16.67 / 16.90 ms |

重复帧检测在采集线程上的耗时（真实采集卡，1080p YUY2）：p50 0.075 ms，p99 0.14 ms。

### 6.2 自适应补帧（30 帧内容 → 60 fps）

真实显示器，合成源模拟 60 Hz 信号里的 30 帧内容（`--synthetic --synthetic-content 30 --interp vfx`，auto 模式）：

* 约 0.8 s 识别出 30 fps，探测选 VRR，输出 60.0 fps（×2）。
* 稳态 D 21.5 ms，最新源帧到达 → 翻页 21.1 / 23.7 ms，0 迟到。
* 理论值 (k−1)/k·2P + lead + 余量 ≈ 20.7 ms。

离线仿真（`pacing_test`，60 Hz 信号、1.5 ms 抖动、20 ppm 漂移）：

| 场景 | 输出 | 迟到 | D p50（理论） |
|---|---|---|---|
| 30 帧内容，VRR k=2 | 60 fps，t ∈ {0, 0.5} | 0 | 21.42 ms（20.67） |
| 30 帧内容，VRR k=4 | 120 fps | 0 | 29.74 ms（29.00） |
| 30 帧内容，固定 120 / 165 Hz | 120 / 165 fps | 0 | 31.20 / 34.56 ms |
| 24p 3:2，VRR k=2 | 48 fps | 0 | 33.88 ms |
| 60→30→60 切换（检测器驱动），VRR k=2 | | 0 | 13.08 → 21.47 → 13.11 ms |
| 60 帧内容中静止 1 s | 保持 120 帧 | 0 | D 13.09 → 最大 13.12 ms |

节奏检测：60 / 30 / 24p / 40 fps 分别识别为 1 / 2 / 2.5 / 1.5；60↔30 切换约 0.9 s；静止画面不触发切换。

### 6.3 声音（真实设备）

采集端 "HDMI (UGREEN 25173)" 按 ContainerId 自动匹配，输出 "Speakers (Realtek USB Audio)"，格式为 48 kHz / 2 ch / float32，两端设备周期都是 10 ms。

* 采集 → 播放：45 ms，缓冲稳定在 35.0 / 35.0 ms 目标值，速率微调稳定在 ±20 ppm 以内。
* 视频同时运行时，40 s 内 0 欠载：音频在视频采集启动之后才开始，欠载时缓冲自动加大。最初的版本和视频同时启动，前 5 s 欠载 55 次。
* 自动同步：视频延迟设为 100 ms 时，音频准确跟到 100.0 ms；从 100 改到 150 ms 时，约 14 s 平滑过渡。
* 线程挂起 150 ms / 400 ms / 2.5 s 后都能自动恢复；`Stop()` ≤ 10 ms。
